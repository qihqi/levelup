# AI 策略：规则来源、评分与扩展

默认策略 `rule_based`（记牌策略 AI）把牌理拆成特征，对合法候选动作逐条加减分，选总分最高的动作。`basic`（基础 AI）保留改动前的原版选择逻辑，便于陪练与对照。房主可在创建房间、等待开局或两局之间选择，整桌 AI、托管和提示使用同一策略。

`xgboost_play`（XGBoost 出牌 AI）使用同一接口，以全信息教师标签训练的树模型排名出牌；亮主和扣底仍使用记牌策略。数据、教师搜索边界、模型与复现步骤见 [出牌模型说明](PLAY_MODEL.md)。

`search`（搜索 AI，最多 30 秒）用记牌和 XGBoost 推荐候选，对符合公开信息的模拟手牌进行续局比较。搜索仅影响出牌，不读取其他玩家的实际手牌；服务端在后台进程运行模拟，并检查结果是否仍对应当前回合。见 [搜索 AI 说明](SEARCH_AI.md)。

## 搜集到的牌理与取舍

查阅日期：2026-09-10。下列是玩家经验和推演，彼此有打法差异，不是统一的最优策略证明；数值权重由本项目设计，并非来源中的数字。

| 来源 | 采用的观点 | 本项目的取舍 |
| --- | --- | --- |
| [百度经验：升级拖拉机（80分）攻略——基础篇](https://jingyan.baidu.com/article/fa4125ac0e8f2928ac7092b3.html) | 扣底尽量做短门缺门、少埋分；谨慎处理分对和甩牌 | 以合法 8 张扣底方案整体评分；保 A、保牌型和少埋分与做缺门同时比较。甩牌只生成公开信息能证明各组合均为同门最大的方案。文中部分翻倍规则与本桌不同，不迁移。 |
| [百度经验：扑克牌拖拉机怎样打？](https://jingyan.baidu.com/article/fec7a1e53d77655090b4e7e6.html) | 获得牌权后先兑现副牌 A 等控制牌；出队友缺门花色供其毙牌 | 只采用结尾的通用策略提示。该文主体混入四副牌规则，因此不作为本桌规则依据。出 A 必须同时评估敌家缺门及主牌风险。 |
| [云间牌馆：IceKing《拖拉机牌理漫谈》](https://tractorcardgame.com/2021/01/tractor_survival_guide/) | 关注分数门槛、分阶段保存控制牌、弱牌配合强牌方、调主要有目的 | 原文是六人玩法，本项目只借鉴通用牌理，把门槛改成本桌的 5、40、80、120…；不照搬六人叫牌标准，不把 Q/J 等约定信号当成确定事实。 |

用户提出的“AA 已出，K 就是新的大牌”落实为**两副牌计数**：自己的手牌、公开已出的牌、庄家本人扣下的底牌均从可能在外的牌中扣除。未见到的隐藏底牌仍按可能在外处理，避免凭空认定某张牌已经不在敌家手上。

## 执行流程

```text
Game → observe(game, seat) → 不可变 AIContext
     → generate_candidates(context) → 合法候选动作
     → AIStrategy.rank(context, candidates) → 评分与理由
     → 选择最高分 → Game.act 再次验牌 → WebSocket 广播
```

`AIContext` 只含本人的手牌、座位、主牌/级牌、庄家、闲家得分、各座位张数、本墩公开牌、之前所有墩、亮主记录，以及庄家本人知道的底牌。它没有 `Game` 引用，也没有其他人的手牌。牌和集合使用冻结数据类/tuple，换一组同张数的隐藏牌不会改变 AI 的观察或排名。记牌从快照重建，重连和换策略不丢记忆；新局自然清空旧记忆。

摸牌期间，手牌只包含已经摸到的牌，尚未发出的牌堆和隐藏底牌不进入观察。AI 在自己的手牌或公开亮主发生变化后等待约 0.7 秒，再重新评分；与真人一样能在摸牌中亮主、反主或加固。记牌策略的亮主牌力门槛按已摸张数 / 25 缩放，避免用完整手牌的门槛阻止早期亮主。候选 `pass` 表示暂时等待，不推进回合；摸牌结束后的 60 秒窗口也允许 AI 反应。

`Knowledge` 的最大牌判断按当前级牌排序和牌型进行：

- 单 A 可压住同门所有更小单牌；另一个同花色 A 等大，后出不能压先出。
- K 只有在两张同花色 A 都已计入已知范围后，才被认定为同门最大单牌。
- 对 K 判断外面是否仍可能存在**完整的对 A**，不是只检查还有没有单 A。
- 拖拉机按当前级牌压缩后的相邻序列判断；副级牌等大，不错误连接成拖拉机。
- 确定缺门来自“必须跟花色时垫出了别门牌”。不把垫 Q、垫 A 等经验信号当作确定缺门。
- “同门最大”不等于“不会被毙”。毙牌风险独立计算，并参考敌家是否还可能持有匹配的主牌组合。
- 未知缺门使用基于公开剩余张数的均匀分布估计；对子/拖拉机毙牌风险另乘启发式折扣。它不是精确的后验概率。

## 主要加减分

总分为 `sum(特征值 × 权重)`。所有权重及中文理由集中在 `levelup/ai/rule_based.py` 的 `RULES`；以下列出主要项，不同阶段不会全部同时生效。

| 特征 | 默认权重 | 条件与单位 |
| --- | ---: | --- |
| 兑现已知同门最大组合 | +80 | 副牌；主牌使用 0.45 倍 |
| 副牌 A | +18 | 属于同门最大组合时；打 A 时 A 是主牌，不加此项 |
| 短门大牌 | +10 | 除以出牌后该门剩余张数加 1 |
| 敌家毙牌风险 | −145 | 乘估计风险，已知缺门时会大幅降低该门 A 的优先级 |
| 成套领出 | +5 | 每多出一张；因此 AA 倾向整对出 |
| 拆对子 / 拆拖拉机 | −12 / −16 | 按被拆开的对子 / 相邻对子连接计数 |
| 主强时调主 | +64 | 主牌长度和大主控制力足够，外面仍可能有主，且此次调主不是小牌盲调 |
| 出单张给缺门队友毙 | +28 | 乘敌家不能毙牌的估计值；不盲目出对子要求队友有主对 |
| 扣底做缺门 | +27 | 每完整扣掉一门原本持有的副牌 |
| 扣底损失主牌 / 副牌大牌 | −24 / −28 | 每张；与缺门收益权衡 |
| 扣底分数风险 | −1.1 | 每分；手中剩余主牌很强时减半 |
| 取得牌权 | +24 | 乘仍未出牌的敌家无法反超的安全度估计 |
| 本墩得分 / 送敌分 | +2.6 / −2.8 | 每分，结合当前赢家与后手风险 |
| 队友安全领先时送分 | +1.2 | 额外每分奖励；安全度至少 0.85 |
| 无益地压过队友 | −24 | 自己接牌后安全度没有明显提升 |
| 消耗普通牌力 / 主牌 / 王 | −0.6 / −4.5 / −5 | 牌力、主牌张数与王张数分别计费 |
| 无分墩毙牌 | −24 | 末墩除外 |
| 升级门槛 | ±24 | 当前墩可能影响下一得分门槛时 |
| 末墩 | ±80 | 争夺牌权，另加估算底牌分 × 倍数 × 1.5 |
| 残局用尽最后的主 | −23 | 手牌不超过 6 张且还未打完；闲家为 0.8 倍 |
| 反队友的主 | −28 | 需要明显更好的整体主牌实力才抵得过此项 |

对于未知底牌，末墩使用 15 分的保守工程先验；庄家使用自己实际扣下的底牌分数。没有使用服务器中的其他人的实际牌来估计赢牌或抠底概率。

“基础 AI”的排名仅给原版会选择的动作 +1，其余 0，因此保留原行为；它不使用新策略的记牌权重。并列候选按动作和物理牌 ID 稳定排序，方便重现问题。

## 候选动作覆盖范围

- 亮主：枚举合法单级牌、对级牌、王对及不亮；沿用引擎的反主与加固限制。
- 领出：枚举单张、完整对子、所有长度的拖拉机；额外考虑能够证明合法的整门甩牌。
- 跟牌：枚举相同牌型的响应。组合数量不超过 384 时枚举全部；更大的混合组合空间用强制跟牌结构、不同填充顺序、替代结构和局部换牌生成候选。
- 扣底：比较不同短门清空组合、保主/保分/保大牌等排序产生的 8 张方案，并考虑原版方案的一张换牌变体。
- 每个策略接收同一套候选，策略排序不能制造新动作；提交仍由 `Game.act` 再次校验。

所以它不是对所有可能出牌序列的穷举搜索，复杂甩牌和扣底的候选空间也是有界的。排名分数只适合比较当前动作，不可当成跨局牌力或胜率。

## OpenAI Agent

`openai_agent` 使用官方 OpenAI SDK，按当前玩家视角把简明规则、手牌、全部历史墩及当前墩传给模型，要求从合法候选中选一项。亮主、扣底和失败兜底使用记牌策略；支持 Web 异步思考和独立模拟。需安装可选 `agent` 依赖并设置服务器 API Key，配置和日志见 [OpenAI Agent 说明](OPENAI_AGENT.md)。

## 接入新策略

实现 `AIStrategy`，返回全部候选的 `RankedAction`，按分数从高到低排序。在 `levelup/ai/__init__.py` 注册即可；房间的策略接口和前端下拉菜单都读取注册表，无需增加新的条件分支。

```python
from levelup.ai.interface import AIStrategy, RankedAction, Reason, ordered

class MyStrategy(AIStrategy):
    id = "my_strategy"
    name = "我的策略"
    description = "一句话描述打法"

    def rank(self, context, candidates):
        # 示例只奖励多出牌；替换为自己的特征、搜索或模型评分。
        return ordered(
            RankedAction(action, (Reason("shed", "减少手牌", float(len(action.cards))),))
            for action in candidates
        )

# 在 levelup/ai/__init__.py 导入并执行：register(MyStrategy())
```

仅调整现有记牌权重也可复用 `RuleBasedStrategy(weights={"cash_master": 95, "break_pair": -18})`；注册多个变体时使用独立子类指定不同 `id`、名称和描述。实例不保存跨玩家私有状态，使用一次决策的 `AIContext` 即可。

程序内查看排名：

```python
ranked = game.ai_rankings(game.turn, "rule_based")
for choice in ranked[:3]:
    print(choice.json())  # action、ids、score、逐条 reasons
```

WebSocket `hint` 返回相同的前三项数据；用户只会收到自己手牌的候选。房间级策略跨下一局、新比赛和掉线恢复保持不变。正在一局中时锁定，防止频繁切换干扰比赛。

## 验证与初步对比

`tests/test_ai.py` 包含 A 优先、AA 已出后的 K、级牌 A、对子保留、敌家确定缺门、有/无主可毙、后手给队友送分、不盲目压队友、无分墩节省主、末墩抢底、扣短门、避免反队友、分数门槛、所有候选合法、信息隔离和评分可解释性测试。

用 `python -m levelup.bench_ai --seeds 30` 运行 30 组固定初始牌，每组交换两种策略所在的南北/东西队：逐张摸牌版本本次 60 局中记牌策略胜 38 局（63.3%）。每局的发牌种子、策略所在队、闲家分数、庄家和升级结果保存在 [ai-benchmark.json](ai-benchmark.json)。模拟在每张牌后让 AI 立即响应，不等待真实半秒节奏与反应延时；计时仅统计扣底和出牌。这是开发回归样本，未做大样本或真人验证，不能承诺通用胜率。计时会随机器负载变化。

后续可在同一接口下加入更精细的剩余牌概率、队友配合模型、残局搜索或训练策略，而不把这些逻辑重新塞回牌局引擎。
